\begin{abstract}
\noindent
This document provides a comprehensive technical specification for the \texttt{pygnss\_rt} Python package, a production-grade framework for Real-Time Precise Point Positioning with Ambiguity Resolution (PPP-AR). The system integrates with the Bernese GNSS Software v5.4 for core geodetic computations while providing a sophisticated Python orchestration layer for data management, product acquisition, and operational automation.

\vspace{0.5cm}
\noindent
\textbf{Key Features:}
\begin{itemize}[noitemsep,topsep=0pt]
    \item \textcolor{primaryblue}{\textbf{Multi-GNSS:}} GPS (G) + GLONASS (R) + Galileo (E) triple-constellation
    \item \textcolor{primaryblue}{\textbf{Troposphere:}} VMF3 Vienna Mapping Functions for ZTD modeling
    \item \textcolor{primaryblue}{\textbf{Biases:}} CODE OSB (Observable-Specific Signal Biases) for PPP-AR
    \item \textcolor{primaryblue}{\textbf{AR:}} LAMBDA-based integer ambiguity resolution
    \item \textcolor{primaryblue}{\textbf{Database:}} DuckDB embedded analytical database
    \item \textcolor{primaryblue}{\textbf{Downloads:}} Multi-source FTP/HTTPS from CDDIS, CODE, IGN
    \item \textcolor{primaryblue}{\textbf{Networks:}} Five international networks (IGS, EUREF, GB, RGP, Supersites)
\end{itemize}

\vspace{0.5cm}
\noindent
\textbf{GitHub Repository:} \url{https://github.com/georgisalene/pygnss_rt}

\vspace{0.5cm}
\noindent
The package replaces legacy Perl scripts with modern Python, providing improved maintainability, type safety, and extensibility while maintaining full compatibility with the Bernese GNSS Software v5.4 processing engine.
\end{abstract}

\chapter{Database System (DuckDB)}

\section{Why DuckDB?}

\begin{infobox}
\textbf{DuckDB} is an embedded analytical database designed for OLAP workloads. Unlike traditional databases (PostgreSQL, MySQL), DuckDB:
\begin{itemize}[noitemsep]
    \item \textbf{Runs in-process} -- No server setup required
    \item \textbf{Single file} -- Entire database in one \texttt{.duckdb} file
    \item \textbf{Column-oriented} -- Optimized for analytical queries

\chapter{Troposphere Processing}

\section{ZTD to IWV Conversion}

The \pyfile{atmosphere/ztd2iwv.py} module converts GNSS-derived ZTD to meteorologically useful IWV:

\subsection{Mathematical Formulation}

The Zenith Total Delay decomposition:
\begin{equation}
\ztd = \zhd + \zwd
\end{equation}

Zenith Hydrostatic Delay (Saastamoinen, 1972):
\begin{equation}
\zhd = \frac{0.0022768 \cdot P_s}{1 - 0.00266 \cos(2\phi) - 0.00028 H}
\end{equation}

Integrated Water Vapor (Bevis, 1994):
\begin{equation}
\iwv = \frac{10^6 \cdot \zwd}{\rho_w \cdot R_v \cdot (k_2' + k_3/T_m)}
\end{equation}

Mean atmospheric temperature (Bevis empirical):
\begin{equation}
T_m = 70.2 + 0.72 \cdot T_s
\end{equation}

\chapter{Mathematical Foundations}

\section{PPP-AR Observation Model}

Ionosphere-free linear combination:
\begin{equation}
L_{IF} = \frac{f_1^2 L_1 - f_2^2 L_2}{f_1^2 - f_2^2}
\end{equation}

\begin{equation}
P_{IF} = \frac{f_1^2 P_1 - f_2^2 P_2}{f_1^2 - f_2^2}
\end{equation}

\section{State Vector}

\begin{equation}
\vecbold{x} = \begin{bmatrix}
\vecbold{r} \\
\delta t_r \\
\ztd \\
G_N, G_E \\
\vecbold{N}
\end{bmatrix}
\end{equation}

\section{LAMBDA Algorithm}

Integer ambiguity search minimizes:
\begin{equation}
\|\hat{\vecbold{a}} - \vecbold{a}\|_{\mat{Q}_{\hat{a}}}^2 = (\hat{\vecbold{a}} - \vecbold{a})^T \mat{Q}_{\hat{a}}^{-1} (\hat{\vecbold{a}} - \vecbold{a})
\end{equation}

Ratio test:
\begin{equation}
R = \frac{\|\hat{\vecbold{a}} - \vecbold{a}_2\|^2}{\|\hat{\vecbold{a}} - \vecbold{a}_1\|^2} > R_{threshold}
\end{equation}

\section{VMF3 Mapping Functions}

\begin{equation}
m_h(e) = \frac{1 + \frac{a_h}{1 + \frac{b_h}{1 + c_h}}}{\sin e + \frac{a_h}{\sin e + \frac{b_h}{\sin e + c_h}}}
\end{equation}
